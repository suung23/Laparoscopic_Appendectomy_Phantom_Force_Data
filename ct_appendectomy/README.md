# CT + atlas appendectomy scene

`build_scene.py` converts the existing public TotalSegmentator s0042 reconstruction and BodyParts3D appendix, mesoappendix and appendicular artery into a USD stage. It preserves dataset/license metadata and input SHA-256 hashes in `out/ct_appendectomy/scene_manifest.json`.

The source CT has **no appendix mask**. The appendix complex is an atlas graft, translated without scale adjustment to a heuristic point on the right inferior colon. This is **not clinically validated registration**. Use `--anchor X Y Z` to provide a reviewed base position in centred RAS metres. The scene does not yet model insufflation, tissue cutting, bleeding or completion of appendectomy. CT provides geometry, not visible tissue colour; materials are procedural.

## Build

Use the existing asset-processing Python environment (numpy, scipy, trimesh, usd-core):

```powershell
python ct_appendectomy/build_scene.py --source ../appendectomy_lab/assets
```

## Isaac Sim 5.1

Use a separate Python 3.11 environment with `isaacsim[all,extscache]==5.1.0` from NVIDIA's package index. It must not share the Newton Python 3.12 environment. NVIDIA's runtime requires acceptance of the Omniverse license agreement.

```powershell
python ct_appendectomy/run_scene.py --headless --frames 120
python ct_appendectomy/run_scene.py --headless --physics --frames 120
python ct_appendectomy/run_scene.py --headless --rl-smoke --frames 120
python ct_appendectomy/run_scene.py --retraction-probe --interactive
```

Outputs are `endoscope.png` and `report.json` under `out/ct_appendectomy/isaac_probe`. The physics option is a zero-gravity FEM cook/finite-state probe, not a validated grasping environment. It explicitly fails if the deformable API or cooked nodes are missing. No rigid-body fallback is labelled soft-tissue simulation.

The inherited `isaac/vla_env.py` remains the separate rabbit-cell environment. The human hybrid scene has its own `AppendixRetractionEnv` Gymnasium task; it is not a complete appendectomy task. Do not report either a rendered image or a cut gesture as physical appendectomy completion.

## Retraction RL contract

`./run-ct.ps1 -RLSmoke` builds the scene and runs the GPU integration checks. `-Retraction -Interactive` opens the Isaac viewport with the scripted FEM retraction probe. These launchers use separate existing asset and Isaac virtual environments. Set `OMNI_KIT_ACCEPT_EULA=YES` only after accepting the NVIDIA runtime terms. D3D12 is the tested Windows backend; Vulkan crashed on this workstation.

With an initialized SimulationApp, instantiate `AppendixRetractionEnv(app, attached_stage, render_mode="rgb_array")`. The attached stage is generated by `--retraction-probe` or `--rl-smoke`. Only one environment owns the global USD stage at a time; use separate processes for parallel environments.

- Action: three normalized handle displacement increments, 1 mm per unit, bounded to 25 mm from the initial handle position. Two 1/120-second physics steps per action.
- Observation: handle command xyz, mean attached-node displacement xyz, maximum base drift, target lift (8 float32 values). This is privileged state; it is not an image-trained policy.
- Reward: 100 times incremental vertical lift in metres minus 0.001 squared action norm; +1 success or -1 base failure.
- Success: at least 10 mm lift with base drift no greater than 1 mm. Failure: base drift exceeds 1 mm. Time limit: 160 actions, reported as truncation.
- `render()` returns a 640 × 360 endoscope RGB image. No trained policy is included.
- Reset reloads the cooked, attached USD and restores the physics scene. Invalid actions are rejected before state mutation; actions after episode end require reset.

The handle attaches directly to selected FEM vertices. It is **not a surgical forceps contact model**. Zero gravity, estimated tissue parameters and static surrounding organs make this a controlled retraction benchmark. The mesoappendix and artery are visual meshes, not yet mechanically coupled deformable bodies. Cutting, ligation, perfusion, bleeding, trocar/RCM constraints and full surgical completion remain unimplemented.

`requirements-isaac.lock.txt` records the tested Python 3.11 installation; install with NVIDIA's extra package index. Generated assets, caches and logs remain excluded from Git. Public input data remain in the sibling `appendectomy_lab` folder; the Git checkout alone does not contain these datasets. Provenance is captured by the scene builder.

## Windows desktop launcher

Run `./build-launcher.ps1` from the repository root to build `IsaacSimulator.exe`, then open that executable from the user desktop. The launcher starts the existing Python/Isaac installation without a terminal window and writes diagnostics to ignored `.cache/desktop-launch.log`. It uses the NVIDIA EULA acceptance already established for this local installation. Launching a GUI from an automation execution desktop may create a window invisible on the user desktop; use the desktop launcher in that case.

The interactive runner selects `/World/Endoscope` again after the deformable stage reload. Mouse camera navigation may still change its pose. Restarting the scene restores the authored pose. The desktop launcher was observed opening an actual Isaac window; the contact extension was subsequently checked in the GUI with Endoscope selected and the authored pose restored.

## Blunt-tip contact milestone

`./run-ct.ps1 -Contact -Interactive` runs a 5 mm radius kinematic sphere against the base-pinned appendix. The sphere moves 12 mm over 120 frames. No grip attachment is present: tissue responds through PhysX collision. The desktop launcher uses this mode and `--lock-endoscope` to restore the authored camera pose on each interactive frame. Omit this flag when free camera navigation is desired.

`--contact-probe --disable-tool-contact` repeats the same prescribed trajectory with tip collision disabled, providing a negative control. These are mechanics smoke tests, not identified tissue-response validation or surgical-force limits. Zero gravity and estimated material parameters remain. Surrounding organs are not deformable.

Static triangle-mesh colliders are authored for 11 CT structures but disabled by default. `--experimental-ct-contact` enables them for diagnosis. The initial atlas graft overlaps CT anatomy: enabling all CT contacts failed the base-drift/stability gate (about 4.75 mm base drift and 91.9 mm maximum displacement). Do not use that mode for training until registration and initial penetration are repaired. The failed result is retained alongside the successful contact and negative-control reports.
